# 恋猫de小郭 (郭树煜) Flutter 跨端避坑与实战经验调研

## 1. GSYGithubApp 真实项目落地指南

“恋猫de小郭”的开源项目 **GSYGithubApp** 被公认为 Flutter 领域的高质量实战标杆，从该项目中提炼出的落地指南主要包括以下几点：

*   **全方位与全流程的架构参考**：不要仅仅停留在 UI 层面的编写，项目展示了从环境搭建、网络层设计、本地缓存到 Redux/BLoC 状态管理、第三方库适配等全套解决方案。它是帮助开发者从 0 到 1 真正搭建工业级 APP 的参考模板。
*   **多框架横向对比思维**：郭树煜同时维护了该项目的 Flutter、React Native、Weex、Jetpack Compose 及 Harmony ArkUI 版本。在落地跨端项目时，建议采用这种“同款应用横向对比”的思路，深入理解 Flutter 在渲染机制、布局原理与其它框架的本质差异。
*   **关注版本演进与“活”教程**：Flutter 版本迭代较快，项目持续记录了版本升级中 API 的废弃与迁移（如 Null Safety 的适配）。在落地时，要高度关注生态兼容性问题，该项目的 Issues 列表和其撰写的《Flutter 完整开发实战详解》是极佳的避坑指南。
*   **UI 与逻辑分离**：在庞大的项目中，建议严格拆分视图层（Widget）和数据/状态管理层，保持代码的规范性与可维护性，避免“面条式”代码。

## 2. 零基础构建“机酒卡” APP 的核心“不踩坑”建议

针对机酒卡（机票、酒店、信用卡）这类业务逻辑复杂、数据嵌套深、页面跳转频繁的应用，结合郭树煜的实战经验，给出以下核心建议：

### 2.1 网络请求封装（Dio）
*   **单例模式管理**：全局务必采用单例模式维护 `Dio` 实例，确保 `baseUrl`、`connectTimeout`、通用 Headers（如鉴权 Token）的一致性，避免重复创建实例导致的内存泄漏与连接管理问题。
*   **重度依赖拦截器（Interceptors）**：
    *   **请求拦截器**：统一处理鉴权、动态参数（如设备信息、请求签名）、接口防重复提交等。
    *   **响应拦截器**：机酒卡业务的接口状态码通常较多，必须在拦截器中统一处理业务错误码（如 401 登录失效自动跳转、500 服务端异常提示）并返回标准化的数据结构，避免在每个页面单独做 try-catch。
    *   **日志拦截器**：在 Debug 模式下引入 `pretty_dio_logger` 等插件打印完整的请求/响应日志，大幅提升接口联调与排错效率。

### 2.2 JSON 解析
*   **拒绝手动解析，拥抱代码生成**：机酒卡业务的数据模型庞大且嵌套极深（例如复杂的航班行程和报价结构）。郭树煜强烈建议中大型项目**放弃手动 `json.decode`**，必须使用 `json_serializable` 等代码生成库，自动化生成 `fromJson` 和 `toJson`，彻底杜绝手动拼写字段引发的低级异常（如类型不匹配导致界面白屏）。
*   **Isolate 异步解析防卡顿**：当请求长列表数据（如大量酒店列表数据）时，在主线程解析超大 JSON 会导致阻塞。务必利用 `compute` 函数将大 JSON 解析任务丢入独立的 `Isolate`（后台工作线程）中执行，确保界面的滑动帧率和丝滑体验。

### 2.3 路由管理（Navigator）
*   **理解底层原理与选择现代库**：早期的复杂项目常推荐 Fluro，但在如今 Navigator 2.0 时代，处理机酒卡这类拥有复杂深层链接（Deep Link）和多级嵌套路由的应用，推荐使用官方主推的 **GoRouter**。
*   **统一的路由拦截与鉴权**：机酒卡业务有严格的权限要求（如预订酒店必须先登录验证身份）。不要在每一个业务按钮的点击事件里写跳转判断，而应利用路由框架的拦截机制（如 GoRouter 的 `redirect`），实现集中式的权限拦截和统一的路由异常（如 404 页面）处理。
