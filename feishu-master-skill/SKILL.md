# 🚀 Feishu-Master-Skill: 飞书极客进阶与业务自动化指南

这份 Skill 融汇了当前全网最顶尖的飞书极客与企业管理者的核心心智。如果您还把飞书当作一个普通的“打卡+聊天”软件，那么本指南将彻底颠覆您的认知。

我们将从**协作认知**、**数据驱动**到**极客自建应用**，手把手教您如何用飞书搭建超级工作流。

---

## 🧭 执行工作流：先分流，再给方案

**Step 1 · 判断需求类型**（输入：用户原话 → 输出：类型 A/B/C/D）

| 类型 | 典型说法 | 走哪条路 |
|---|---|---|
| A 协作/会议 | 会太多、交接乱、知识沉淀不下来 | 第一重境界：云文档 + 飞阅会 |
| B 数据/业务系统 | 搭任务追踪、CRM、进销存、台账 | 第二重境界：多维表格 |
| C 通知/提醒 | 到期提醒、日报推送、群通知 | 先用零代码：多维表格自动化 或 群「自定义机器人」Webhook；只有需要收消息/按钮回写时才升级到 D |
| D 交互机器人/系统集成 | 机器人要收 @ 消息、卡片按钮回写、接外部系统/大模型 | 第三重境界：自建应用 + 事件订阅 |

混合需求（如「客户跟进 + 到期提醒 + 日报」）一律按 B → C → D 分阶段排期，先建底层数据，再上自动化，最后写代码。

**Step 2 · 直接给完整方案**（按类型输出）
- A：会议/文档改造的具体规则（会前默读时长、评论规范、To-Do @ 到人）
- B：表结构清单（表名｜字段｜字段类型｜关联关系）+ 按角色的视图分配 + 自动化规则（触发条件 → 动作）
- C：零代码配置步骤；确需代码时给最小可运行示例
- D：架构（应用能力｜权限｜订阅事件｜卡片交互）+ 开发顺序
- 用户问「怎么做 / 如何利用」属于概念咨询：直接给完整方案，**不要**先反问前置条件再停下。
- A/B/C/D 只用于内部判断，回复里不写「这属于 B 类」之类标签。

**Step 3 · 🔴 CHECKPOINT · 🛑 STOP**（仅在用户要求「开始写生产代码 / 部署上线 / 批量改写数据」时触发）
逐条确认，任一项为否 → 先给补齐步骤，暂不输出生产代码：
1. 自建应用的权限已申请并发布了版本（管理员已审批）？
2. 底层多维表格流程已人工跑通至少 1–2 周、字段不再大改？
3. App Secret 等凭证放在服务端环境变量，不进代码仓库？

## 🧠 第一重境界：云文档与“异步办公”协作思维

> **极客心法**：“Context, not Control”（提供上下文，而不是控制）。用文档沉淀知识，用划线评论打破部门墙。 —— **李想 (理想汽车CEO) & 老麦 (少数派)**

如果您正在被无尽的群聊、口头交接和冗长的开会消耗精力，请立即切换到“文档驱动”模式：

### 1. 结构化块 (Block) 与多模态嵌套
不要把云文档当成 Word。飞书文档是类似 Notion 的 **Block 结构**容器。
- **做法**：在文档里输入 `/` 插入多维表格、思维导图、流程图等块；知识库按「团队 → 项目 → 文档」三级建目录，新人入职只发知识库首页链接。

### 2. 重塑开会：飞阅会 (Doc-Reading Meeting)
- **做法**：用云文档替代 PPT。会议开头 15 分钟全员**默读 + 划线评论**；剩余时间只讨论未关闭的评论；结论当场写成 To-Do 并 `@` 责任人、填截止日期。

## 📊 第二重境界：多维表格 (Bitable) 与轻量级 ERP 搭建

> **极客心法**：“用关系型数据库的思想代替 Excel，让数据流转自动推着业务走。” —— **齐俊元 (飞书副总裁)**

千万不要把多维表格当成大号的 Excel。它是您不写一行代码就能搭建 CRM、进销存、人事管理系统的“核武器”。

### 1. 底层建库法则：实体与双向关联
- **做法**：一类实体一张表（如《客户》《跟进记录》《合同》），表之间用**双向关联**字段连接，点开客户即可看到全部跟进与合同（Single Source of Truth）。
- **字段类型规则**：负责人/执行人用「人员」字段（才能 @ 和收提醒，不要另建成员表去关联）；状态用「单选」；日期用「日期」；金额用「数字/货币」；汇总用「查找引用」或「公式」。

### 2. 角色分发法则：多维视图 (Views)
- 所有人都在底层同一张表上工作，但根据角色提供千人千面的视图：
  - 销售主管使用 **仪表盘 (Dashboard)** 看数据漏斗。
  - 业务员使用 **看板 (Kanban)** 拖拽进度卡片。
  - 外部客户通过 **表单 (Form)** 直接录入数据。

### 3. AI 与自动化爆发点 (Automation) —— **苍何**的极客玩法
- **AI 字段捷径**：直接在表格列中启用 AI 字段（接入 DeepSeek/飞书大模型），选中长篇需求文档，一键让 AI 自动提取关键指标并转化为结构化标签。
- **自动化流程**（多维表格右上角「自动化」，零代码）：写成「触发 → 条件 → 动作」三段。例：触发＝定时（每天 09:00）→ 查找记录：到期日 在未来 30 天内 且 状态≠已续约 → 对每条记录发送飞书消息给「负责人」字段。常用触发还有「新增记录时」「记录满足条件时」。

## 🤖 第三重境界：开放平台 (OpenAPI) 与自建应用爆发

> **极客心法**：“利用 WebSocket 事件订阅和消息卡片，打造企业的超级智能助理。” —— **Leon (Awesome Feishu)**

当低代码（多维表格）无法满足您对极客自动化的追求时，是时候利用代码接入 OpenAPI 了。

### 0. 只需往群里推消息：自定义机器人 Webhook（零开发）
- 群设置 → 群机器人 → 添加「自定义机器人」→ 复制 Webhook 地址 `https://open.feishu.cn/open-apis/bot/v2/hook/<token>`；安全设置必须开一项（自定义关键词 / IP 白名单 / 签名校验）。
- 调用：`POST` JSON `{"msg_type":"text","content":{"text":"日报：..."}}`；定时推送交给多维表格自动化或服务器 cron。
- 限制：只能发到所在群、收不到消息、按钮不能回调；频率上限 100 次/分钟、5 次/秒。需要其中任一能力 → 走下面的自建应用。

### 1. 自建机器人的业务闭环
- **基座**：开发者后台创建「企业自建应用」→ 开通权限（发消息 `im:message:send_as_bot`、读群 @ 消息 `im:message.group_at_msg:readonly`、读写多维表格 `bitable:app`）→ 创建版本并由管理员审批发布，权限才生效。
- **鉴权**：`POST /open-apis/auth/v3/tenant_access_token/internal`（传 app_id、app_secret）换 tenant_access_token，有效期 2 小时；缓存复用、到期前刷新，不要每次请求都取。
- **入口**：添加“机器人”能力，让员工可以在单聊或工作群里直接与它交互。
- **发消息**：`POST /open-apis/im/v1/messages?receive_id_type=chat_id`，`msg_type` 用 `interactive` 发消息卡片（用卡片搭建工具生成 JSON）。卡片放「同意 / 拒绝」按钮，点击回调到后台后回写多维表格。

### 2. 事件订阅 (Event Subscription) 的开发者最佳实践
如果您的程序需要实时知道“谁创建了一个云文档”、“谁在群里@了机器人”，请配置事件订阅。
- **接收方式**：本地或内网开发用「长连接（WebSocket）」模式，官方 SDK（Python `lark-oapi` / Node `@larksuiteoapi/node-sdk`）直接起客户端，无需公网 IP 和 ngrok；上线有公网地址再按需改 HTTP 回调。
- **收 @ 消息**：订阅事件 `im.message.receive_v1`。
- **3 秒规则**：收到事件 3 秒内返回 200，否则飞书会重推；按 `event_id` 去重。要调大模型等耗时任务 → 先回 200、任务进队列，完成后 `PATCH /open-apis/im/v1/messages/{message_id}` 更新卡片（卡片 config 需 `"update_multi": true`）。

## 🔴 反例与黑名单 (不要做的事)
- ❌ **不要把多维表格当成大号Excel使用**：避免单表冗杂所有数据，一定要用双向关联。
- ❌ **不要开传统的PPT汇报会**：废除冗长宣读，使用飞阅会进行默读与划线评论。
- ❌ **绝不要用纯文本回复自建机器人交互**：必须使用消息卡片进行交互。

## 异常处理与降级策略 (Fallback)

| 触发条件 | 一线修复动作 | 仍失败兜底方案 |
|---|---|---|
| 多维表格数据庞大卡顿或逻辑错乱 | 检查双向关联，拆分实体表，利用仪表盘视图筛选 | 退回标准云文档单表记录，舍弃自动化流 |
| 自建机器人API回调失败/无响应 | 检查事件订阅配置，切换为WebSocket长连接模式 | 降级为手动在群内发送提醒卡片 |
| 团队成员不习惯文档协同导致推进受阻 | 安排飞阅会强制习惯，@到人落实To-Do | 放弃全盘推行，先在核心小组作为试点运行 |
